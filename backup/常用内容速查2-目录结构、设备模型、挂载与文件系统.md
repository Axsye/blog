# 1. Linux 文件类型

`ls -l` 最前面的 10 个字符：

```text
-rwxr-xr-x
│└──────── 9 位权限
└───────── 文件类型
```

## 【必记】文件类型字符

| 字符 | 英文 | 含义 |
|---|---|---|
| `-` | regular file | 普通文件 |
| `d` | directory | 目录 |
| `l` | symbolic link | 符号链接 |
| `c` | character device | 字符设备 |
| `b` | block device | 块设备 |
| `p` | pipe / named pipe | 管道 / 命名管道 |
| `s` | socket | 套接字 |

## 【记忆方法】

```text
d → directory
l → link
c → character
b → block
p → pipe
s → socket
```

除了 `-`，基本都来自英文关键词首字母。

# 4. Pipe

```text
p = pipe
FIFO = First In, First Out
```

Pipe 是 IPC（Inter-Process Communication，进程间通信）的一种方式。

Shell 中：

```bash
command1 | command2
```

数据流：

```text
command1 stdout
       ↓
      pipe
       ↓
command2 stdin
```

例如：

```bash
dmesg | grep uart
```

表示：

```text
dmesg stdout → grep stdin
```

# 8. 文件权限与父目录权限

这是非常重要的一组区别。

## 【必记】

```text
修改文件内容 → 看文件本身的 w
删除文件     → 看父目录的 w + x
```

例如：

```text
dr-x------ project/
-rwxrwxrwx project/app
```

可以修改 `app` 内容，但不能删除它，因为父目录没有 `w`。

## 【记忆方法】

> 文件决定“能不能改里面的东西”  
> 目录决定“能不能增删里面的名字”

```text

```


# 11. Owner / Group / UID / GID

例如：

```text
-rwxr-x--- 1 alice developers ... myapp
             ↑       ↑
           owner    group
```

权限匹配顺序：

```text
是 owner？
→ user 权限

否则属于 group？
→ group 权限

否则
→ others 权限
```

三组权限不是累加。

## UID / GID

```text
UID = User ID
GID = Group ID
```

Linux 内核更核心地使用数字 ID。

```text
root → UID 0
```

# 13. root / sudo


# 14. `id` / 用户组

例如：

```text

```

含义：

```text

```

```text

```

# 15. `usermod -aG`

```bash
sudo usermod -aG dialout alice
```

拆解：

```text
-a = append
-G = supplementary Groups
```

## 【必记】

```text
-aG = append Groups
```

不要轻易遗漏 `-a`：

```bash
usermod -G dialout alice
```

可能覆盖原有附加组。

修改组后通常需要注销并重新登录，再用：

```bash
id
```

确认。

# 16. 串口权限实例



这在 Ubuntu 连接 Zynq / PolarFire SoC 串口时非常常见。

# 24. Shell 重定向

```text
>    stdout 覆盖写入
>>   stdout 追加写入
2>   stderr 覆盖写入
2>>  stderr 追加写入
<    stdin 输入重定向
2>&1 stderr 指向 stdout 当前的位置
|    前一个 stdout → 后一个 stdin
```

## `2>&1`

```bash
myapp > all.log 2>&1
```

结果：

```text
stdout → all.log
stderr → all.log
```

## 【必记】顺序有意义

Shell 从左到右处理重定向。

```bash
myapp 2>&1 > all.log
```

最终：

```text
stdout → all.log
stderr → terminal
```

# 26. `find`

结构：

```text
find WHERE CONDITIONS
```

常见：

```bash

find . -type d -name "driver"
find . -type f -iname "*.h"
```

条件：

```text
-type f → regular file
-type d → directory
-name   → 名称匹配，区分大小写
-iname  → 名称匹配，忽略大小写
-maxdepth N → 最大深度
-mindepth N → 最小深度
```

深度：

```text
.               → depth 0
./file.txt      → depth 1
./src/main.c    → depth 2
```

# 42. Boot ROM / Bootloader / U-Boot

## Boot ROM

```text
Boot ROM
= 芯片内部固化的早期启动代码
```

典型职责：

```text
根据 boot mode 找到下一阶段程序
从 SD / eMMC / QSPI / NAND / JTAG 等加载
```

## U-Boot

```text
U-Boot = Universal Boot Loader
```

不是“专门启动 Linux”，而是通用嵌入式 Bootloader。

常见职责：

```text
初始化部分硬件
访问存储 / 网络
加载 Kernel
加载 DTB
准备 kernel command line
启动 Kernel
```

---

# 43. Early Boot / FSBL

某些平台还需要：

```text
FSBL = First Stage Boot Loader
```

用于非常早期的初始化，例如：

```text
DDR
Clock
Pinmux
SoC 基础初始化
```

更通用的思维：

```text
Power On
   ↓
Boot ROM
   ↓
Platform-specific Early Boot Firmware
   ↓
U-Boot
   ↓
Kernel + DTB
```

不同 SoC 的具体启动阶段名称可能不同。

```text
       ↓

       ↓
```

```text

   ↓
```

# 45. Root Filesystem

```text
rootfs = root filesystem
```

Linux Kernel 不是完整 Linux 系统。

Kernel 负责：

```text
调度
内存管理
驱动
网络
文件系统
系统调用
```

rootfs 提供：

```text
/bin
/etc
/lib
/usr
/var
你的程序
动态库
配置
init
```

## 【必记】

```text
Kernel → 提供系统能力
rootfs → 提供用户空间
```

rootfs 最终挂载为：

```text
/
```

# 46. Kernel initialization 与 Userspace initialization

```text
Kernel initialization
→ CPU / MMU / memory / driver / scheduler ...

Userspace initialization
→ init / systemd / services / network / applications ...
```

如果出现：

```text
No working init found
```

优先怀疑：

```text
rootfs
init
动态库
路径
执行权限
```

而不是“Kernel 完全没运行”。

# 47. `/lib` / 动态库

```text
→ libraries
```

```text

...
```

如果出现：

```text

```

# 48. `.o` / `.a` / `.so`

```text
.o  = object file
.a  = archive = static library
.so = shared object = shared / dynamic library
```

## 静态链接

```text
myapp.o + libfoo.a
       ↓
      linker
       ↓
     myapp
```

所需库代码被链接进最终程序。

运行时通常不再需要 `libfoo.a`。

## 动态链接

```text
myapp
  ↓ runtime
libfoo.so
```

运行时仍需找到兼容的 `.so`。

## 【记忆方法】

```text
.a  → 链接时装进去
.so → 运行时找过来
```

# 50. `/usr/include`

```text
/usr/include
→ C / C++ 系统头文件
```

主要用于**编译阶段**，不是运行阶段。

例如：

```text
/usr/include/stdio.h
```

头文件：

```text
告诉编译器函数 / 类型“长什么样”
```

库：

```text
提供真正实现代码
```

如果报：

```text

```

优先考虑：

```text

-I
头文件是否存在
sysroot
```

## 【记忆方法】

```text

```

# 51. Cross Compiler 与 Sysroot

## Cross Compiler

用于在 Host 上生成 Target 架构的机器码。

例如：

```text
Host   = x86_64 Ubuntu
Target = ARM64 Zynq
```

或：

```text
Target = RISC-V PolarFire SoC
```

## Sysroot

```text

→ 为目标系统准备的一套“伪根目录”
```

通常包括：

```text

├── usr/include
├── usr/lib

```

## 【必记】

```text

```

不能拿 x86_64 的 `.so` 给 ARM64 程序链接。

# 56. `/usr/lib` vs `/var/lib`


# 57. `/var`

# 60. Block Device / Partition / Filesystem / Mount Point

这是存储模型里最关键的一组。

```text
Physical Storage
   ↓

   ↓

   ↓
Filesystem
   ↓
Mount
   ↓
Mount Point
   ↓
Files
```

例：

```text

   ↓

   ↓
/dev/mmcblk0p2
   ↓
ext4
   ↓
mount
   ↓

```

## 【必记】

```text

```

# 61. `mount`

```text
mount = 挂载
mount point = 挂载点
```

例如：

```bash
mount /dev/mmcblk0p1 /mnt/sdcard
```

表示：

> 把 `/dev/mmcblk0p1` 中的文件系统接入 Linux 目录树，并通过 `/mnt/sdcard` 访问。

挂载点**不一定**必须在 `/mnt`。

常见：

```text
/mnt   → 临时 / 手工挂载
/media → 桌面环境可移动介质
/data  → 项目自定义数据分区
/boot  → boot 分区
/      → root filesystem
```

---

# 62. Mount 遮挡原目录内容

如果：

```text
/data/a.txt
```

原本存在，然后另一个 filesystem mount 到 `/data`：

```text
a.txt 不会被删除
只是暂时看不见
```

`umount` 后会重新出现。

## 【必记】

```text
mount
→ 改变当前目录入口看到的文件系统

不是
→ 删除原目录内容
```

---

# 63. `umount`

命令是：

```bash
umount /mnt/sdcard
```

不是 `unmount`。

作用：

```text
unmount filesystem
```

# 73. 当前应形成的排障思维

以后遇到嵌入式 Linux 问题，不要只问“程序为什么不工作”，而要先判断层级：

```text
板子没有启动？
→ Boot ROM / Bootloader

Kernel 没起来？
→ Kernel Image / bootargs / DTB

设备没有？
→ Device Tree / Driver / /sys / dmesg

设备节点权限不够？
→ /dev / owner / group / chmod

IRQ 没发生？
→ /proc/interrupts

程序执行不了？
→ file / architecture / permission

.h 找不到？
→ include / sysroot

.so 找不到？
→ dynamic library / rootfs

分区看不到文件？
→ block device / filesystem / mount

系统盘满？
→ df / du
```

这套“按层排查”的思路，比单纯背命令更重要。
